# Closure checklist — leave nothing open

Load this to close a project or phase cleanly. Walk each section top to bottom; mark every
item done or waived with a reason. Examples use the running sample project: **Helios**, a
customer self-service portal.

## Acceptance and sign-off
- [ ] All in-scope deliverables are complete (or descoped through change control).
- [ ] Deliverables meet the agreed acceptance criteria and definition of done. See
  `quality-management`.
- [ ] Outstanding defects are resolved or formally accepted as known exceptions.
- [ ] The sponsor / customer has given formal written acceptance.
- [ ] Any accepted exceptions or open items are recorded with an owner.

## Handover to operations / benefits owner
- [ ] The product, environments, and access are transferred to the run team.
- [ ] Operational documentation, runbooks, and support arrangements are in place.
- [ ] A named owner is accountable for running the product and for its benefits.
- [ ] Training or knowledge transfer for the run team is complete.
- [ ] See `benefits-realization.md` for the benefits side of the handover.

## Administrative closure
- [ ] All issues and actions are closed or transferred with an owner (from the issue log).
- [ ] Open risks are closed or handed to the run team with the register.
- [ ] The team and shared resources are formally released.
- [ ] Project records and key decisions are archived in a findable place.
- [ ] Stakeholders are notified that the project is closing (see `project-communication`).

## Financial closure
- [ ] Final costs are reconciled against the cost baseline; variance is explained. See
  `cost-management`.
- [ ] All invoices are received, approved, and paid; purchase orders are closed.
- [ ] Contracts and supplier engagements are formally closed.
- [ ] Remaining budget / contingency is released back.

## Lessons and reporting
- [ ] A post-project review is held and lessons are captured. See `lessons-learned`.
- [ ] Benefits tracking has a named owner and review dates (against the `business-case`).
- [ ] The closure report is completed and signed off (see `closure-report.md`).

## Common gaps caught here
- A go-live celebrated while invoices and contracts sit open for months.
- A handover with documentation but no named owner to actually run the product.
- Lessons "discussed" verbally but never recorded or routed for reuse.
- The project closed with no plan for who checks whether the benefits arrive.
